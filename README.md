# Todo Notes

Однопользовательское приложение для заметок со списками дел. При открытии главная показывает до 30 последних заметок. У каждой карточки видны до четырёх пунктов, прогресс и дата изменения. Кнопка «Показать ещё» загружает следующую страницу и исчезает в конце списка. В редакторе можно менять текст, отмечать пункты, отменять и повторять действия. Приложение предназначено для локальной копии одного доверенного пользователя. Все клиенты одного экземпляра работают с общей базой без авторизации.

## Запуск

```sh
docker-compose up
```

Откройте [localhost:8080](http://localhost:8080). В Compose V2 та же команда пишется `docker compose up`. При первом запуске Nitro применит миграции и создаст пустую базу в `/data/notes.sqlite`. Готовность можно проверить по [ответу сервера](http://localhost:8080/api/readyz). Чтобы проверить сохранность данных, сохраните заметку, скопируйте её адрес, выполните `docker compose restart app` и снова откройте этот адрес. База хранится в именованном томе `notes-data`.
По умолчанию Compose публикует порт только на `127.0.0.1`. Адрес публикации задаёт `NOTES_BIND`.
Сервер принимает Host `localhost`, `127.0.0.1` и `[::1]`. Для своего адреса задайте `NUXT_ALLOWED_HOST` без схемы и порта. Для остальных имён сервер возвращает 403 и на страницах, и в API.
Публикация для нескольких пользователей требует отдельного решения об аутентификации.

Для локального запуска и проверок нужны Git, версия Node из `.nvmrc` и версия pnpm из поля `packageManager` файла `package.json`. Выполняйте команды в корне клона.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Локальный адрес — [localhost:3000](http://localhost:3000). По умолчанию сервер создаёт `.data/notes.sqlite`. Переменная `NUXT_DATABASE_PATH` задаёт другой путь. better-sqlite3 поставляет готовые нативные модули, включая Linux musl x64 и arm64.

```sh
pnpm build
NITRO_HOST=127.0.0.1 node .output/server/index.mjs
```

Без `NITRO_HOST` собранный сервер и `pnpm preview` слушают все сетевые интерфейсы, поэтому для локальной копии адрес ограничен loopback. Для переноса сборки скопируйте всю папку `.output` на систему с совместимыми Node, ОС и архитектурой. Запускайте из родительского каталога `.output` или задайте абсолютный `NUXT_MIGRATIONS_PATH` до скопированной папки `.output/server/migrations`. Процесс Nitro раздаёт SPA и API. При запуске он открывает одно соединение SQLite, включает WAL, внешние ключи и ожидание блокировки до пяти секунд.

Для удаления всех локальных заметок и черновиков остановите приложение и выполните `pnpm db:reset`.
Команда очищает записи в файле `NUXT_DATABASE_PATH` (по умолчанию `.data/notes.sqlite`), сжимает файл без остатков удалённого текста и сохраняет схему.
Для полного сброса контейнерной копии `docker compose down -v` удаляет сервис и том со всеми записями.
Следующий запуск создаёт пустую базу.

Для проверки списка на объёме запущенное приложение можно наполнить заметками с разным содержимым: `pnpm db:seed` создаёт 200 заметок через API на `http://localhost:8080`. Адрес и число задают `--url` и `--count`, например `pnpm db:seed --url http://localhost:3000 --count 50`. Каждое создание удаляет несохранённый черновик новой заметки, поэтому перед наполнением сохраните или удалите его.

## Управление

| Действие                       | Клавиши                           |
| ------------------------------ | --------------------------------- |
| Отменить                       | Ctrl+Z или ⌘Z                     |
| Повторить                      | Ctrl+Shift+Z, ⌘Shift+Z или Ctrl+Y |
| Вставить пункт после текущего  | Enter в поле пункта               |
| Удалить пустой пункт           | Backspace                         |
| Перейти между кнопками диалога | Tab, Shift+Tab                    |
| Закрыть диалог                 | Escape                            |

Горячие клавиши редактора работают при русской раскладке и внутри полей. Сохранение оставляет редактор открытым. При выходе с правками можно сохранить черновик и вернуться к списку. Действие «Отменить правки» после подтверждения возвращает последнюю сохранённую версию, удаляет черновик и оставляет редактор открытым. Результат сохранения, удаления и отмены сообщается уведомлением в углу экрана.

## Архитектура

```text
src/
├── app/               страницы, раскладки и плагины Nuxt
├── core/notes/        клиентский домен заметок
├── public/            статические файлы
├── server/            маршруты Nitro, модуль заметок и SQLite
└── shared/
    ├── contract/      типы и правила HTTP и заметок
    └── uikit/         компоненты интерфейса
```

Клиент и сервер используют `@shared/contract/…`. Внутри контракта разрешены только импорты его собственных модулей.

| Слой                                           | Ответственность                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/app/`                                     | Тонкие страницы списка и редактора, раскладка, хост диалогов и уведомлений. В точке сборки зависимостей `plugins/services.ts` плагин Nuxt создаёт HTTP-клиент, API, адаптер и сервис заметок, подключает часы, генератор ID и канал вкладок.                                                                                                                    |
| `src/core/notes/`                              | `api.ts` описывает вызовы HTTP, `adapter.ts` преобразует ответы в модели, `service.ts` выбирает действия при сохранении, восстановлении и конфликте версий. Представления списка и редактора сами загружают данные через `useLazyAsyncData` и на время запроса показывают скелетоны. В домене Pinia хранит только сессию редактора с текущим вводом и историей. |
| `src/shared/`                                  | Базовые элементы в `components/base/`, кнопки и модальные окна в `uikit/`, общие сервисы времени, HTTP и обмена между вкладками. UI-сторы Pinia управляют стеком диалогов и стеком уведомлений об успехе и ошибке.                                                                                                                                              |
| `src/shared/contract/`                         | Общие для клиента и сервера типы заметок и операций, лимиты ввода, нормализация и версии формата черновика.                                                                                                                                                                                                                                                     |
| `src/server/api/`, `src/server/modules/notes/` | Маршрут проверяет параметры и тело запроса по DTO-схемам Zod и передаёт данные сервису. Сервис проверяет версию и задаёт границы транзакции. Репозитории читают и записывают SQLite через Drizzle.                                                                                                                                                              |

Репозиторий выбирает страницу заметок со счётчиками и отдельно получает превью только для записей этой страницы. При обновлении сервис в одной транзакции заменяет пункты, увеличивает версию заметки и удаляет её черновик. Колонка `position` сохраняет порядок пунктов.

В `src/server/database/migrations/` лежат SQL и журнал Drizzle Kit. После изменения схемы новые миграции создаёт `pnpm db:generate`. Сборка копирует их в `.output/server/migrations`. При старте плагин Nitro применяет ожидающие миграции и проверяет внешние ключи перед обработкой запросов.

## История и черновики

Редактор хранит до 50 операций. Изменение текста запоминает исходное и итоговое значение, добавление и удаление пункта — сам пункт и его позицию. Отметка выполнения занимает один шаг. Непрерывный ввод в одном поле объединяется до потери фокуса, смены поля или паузы 700 мс. Кнопка отмены учитывает уже введённый текст, даже пока курсор в поле. Новая правка после отмены очищает ветвь повтора.

Через 800 мс после последней правки клиент записывает на сервер черновик с содержимым, базовой версией и обеими ветвями истории. Скрытие вкладки и событие `pagehide` запускают запись сразу. Для тела JSON размером до 60 КиБ включительно клиент запрашивает `keepalive`. Более крупную отправку браузер может прервать при закрытии страницы.

## HTTP API

| Метод и путь            | Результат                                                                                          |
| ----------------------- | -------------------------------------------------------------------------------------------------- |
| GET /api/notes          | Страница { items, nextCursor, total }, параметры limit, cursor и q, счётчики и сокращённое preview |
| GET /api/notes/:id      | Полная заметка с массивом todos и версией                                                          |
| POST /api/notes         | Создание по полям title и todos, ответ 201 с заметкой                                              |
| PUT /api/notes/:id      | Обновление по title, todos, baseVersion и необязательному force                                    |
| DELETE /api/notes/:id   | Удаление заметки, пунктов и черновика, ответ 204                                                   |
| GET /api/drafts/:key    | Черновик или пустой результат. Ключ — id заметки или new                                           |
| PUT /api/drafts/:key    | Запись объекта draft; observedVersion позволяет сохранить черновик после обнаруженного конфликта   |
| DELETE /api/drafts/:key | Удаление черновика, ответ 204                                                                      |
| GET /api/healthz        | Жизнь процесса                                                                                     |
| GET /api/readyz         | Готовность SQLite, проверенная запросом по журналу миграций                                        |

Для POST, PUT и запросов на запись с телом укажите `Content-Type: application/json`. DELETE без тела можно отправить без Content-Type. Для всех изменяющих запросов чужой Origin или `Sec-Fetch-Site: cross-site` даёт 403. Неподдерживаемый тип содержимого при записи даёт 415.
Список сортируется по updatedAt по убыванию и id по возрастанию. По умолчанию выдаётся 30 заметок, максимум 100. Поле total содержит число всех заметок, а при поиске — число найденных. Параметр q ищет подстроку в названии и пунктах без учёта регистра.
Передайте nextCursor в следующем запросе. Значение null означает последнюю страницу. Текст первых четырёх пунктов сокращается до 140 символов.

Ошибки содержат `code`, `category`, `message` и `requestId`. Ответ 400 означает ошибку входных данных, 404 — отсутствие заметки или маршрута, 409 — устаревшую версию, 413 — превышение 1 МиБ. Если сервер не может прочитать сохранённый черновик, он возвращает 500 с кодом `DRAFT_UNREADABLE`.

Ошибки отдельных полей приходят в `fieldErrors`. Сервер пишет структурированные JSON-логи Pino в stdout. По `requestId` из ответа можно найти запись об ошибке. При записи логгер скрывает чувствительные поля, включая заголовок и текст заметки.

## Граничные случаи

- Редактор не сохраняет заметку, пока в ней есть пустой пункт: пункт подсвечивается, отметить его нельзя, подсказка объясняет причину. Сервер для любых клиентов обрезает пробелы и отбрасывает пустые пункты. Для сохранения требуется название или заполненный пункт. Заметка без названия отображается как «Без названия». Пределы — 200 символов в названии, 500 в пункте, 200 пунктов в заметке.
- После перезагрузки редактор предлагает восстановить черновик и показывает время правки. Черновик у заметки один, он удаляется после сохранения, отмены правок или по кнопке «Удалить черновик». Если отложить решение, черновик сохраняется, а новые правки не перезаписывают его, пока он не восстановлен или не удалён. Если базовая версия устарела, пользователь видит предупреждение. Для отсутствующей заметки доступен возврат к списку. Уцелевший черновик можно открыть как новую заметку.
- Вкладки обмениваются уведомлениями через BroadcastChannel. При возврате фокуса редактор проверяет версию через API. При удалении открытой заметки можно сохранить локальную копию под новым ID. При конфликте версий перезапись требует подтверждения.
- Ошибка запроса отображается в интерфейсе. После ошибки сохранения текст и история остаются в редакторе.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install --with-deps chromium
pnpm test:e2e
```

`pnpm lint` запускает ESLint, Stylelint, Prettier и проверки кода репозитория. `pnpm check` последовательно выполняет lint, typecheck и Vitest. Тесты истории используют последовательности операций fast-check, интеграционные тесты — SQLite и штатные миграции. `pnpm test:e2e` собирает приложение и запускает Playwright в Chromium с отдельной временной базой. Сценарии охватывают догрузку, восстановление черновика, конфликт вкладок и клавиатуру. Axe проверяет список, редактор, диалог, отсутствующую заметку и страницу ошибки при ширине 320 px в обеих темах.
